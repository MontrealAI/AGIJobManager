# Project-bound Computer Use proposals

`four-repo-computer-receipt.mjs` composes the current Alpha native Computer Use handoff/return with the shared Jobs receipt evidence inspector. The code-installed inspectors must come from the exact published four-repository compatibility set. Imported payloads cannot supply code, select a deployment, dispatch a worker, reserve funds or approve settlement.

`createComputerReceiptDraft(inputs, options)` accepts exact `handoffRaw`, `returnRaw` and `reportRaw` strings. Options are `budgetUSDC`, canonical `createdAt`, Alpha's `inspectAlphaReturn`, and Jobs' `inspectComputerReceiptEvidence` installed under the `inspectComputerEvidence` option. The shared inspector replays the exact frozen public supplier laboratory, verifies native receipt semantics and separately recomputes its allocation. This establishes consistent historical evidence; authenticated execution, independent economic review and production qualification remain separate requirements.

The Manager route independently selects USDC with six decimals. Its proposed budget is never a conversion of an AGIALPHA allowance, a provider quote or observed expense. The exported `createJob` intent has no deployment, specification URI, duration, details, signature or transaction selected. These terms require their own review before commissioning. `inspectComputerReceiptDraft` replays shared evidence and Manager policy rather than trusting an outer checksum.

Use public, non-personal inputs only. Retain Ubuntu Hardhat creation with local hidden ephemeral deployer-key entry: never store or print a key, put it in arguments, `.env`, history or logs. Governance remains Ledger on Mac Studio. Previous deployments are read-only; ENS configuration and all real-wallet or on-chain actions remain outside this source integration.

Run local policy regressions with `node --test scripts/integrations/four-repo-computer-receipt.test.mjs`. The Fleet source integration kit supplies actual pinned Alpha and Jobs inspectors for the native browser compatibility test. Local policy doubles alone are not browser or settlement evidence.

The separate `hardhat/scripts/four-repo-computer-lifecycle.cjs` fixture exercises accepted mock-USDC work and a rejected-work refund on a disposable EDR chain. It checks every compiler input against installed source, allows only the known disposable test accounts and chain 31337, and refuses HTTP, forks and additional networks. Its reviewer votes are controlled test inputs, not independent review. It never changes a previous deployment.

Supply these public test settings directly to the fixture process. No `.env` file or operator key is used:

| Setting | Required public input |
| --- | --- |
| `FQR_DRAFT_FILE` | Absolute path to the bounded synthetic Manager draft |
| `FQR_ALPHA_SOURCE` | Absolute path to the reviewed exact Alpha source checkout |
| `FQR_JOBS_SOURCE` | Absolute path to the reviewed exact Jobs source checkout |
| `FQR_EVIDENCE_FILE` | Absolute new evidence path; existing files are refused |
| `FQR_ARTIFACTS_DIR` | Optional absolute compiled artifact directory; every source and optimizer input must still match |

Run the signing-boundary regressions with `node --test hardhat/test/four-repo-computer-lifecycle.test.cjs`. Full lifecycle evidence records actual disposable receipts, mock token transfers and balances; it establishes no real-wallet operation, actual native browser run, independent economic review or production approval.

The disposable `hardhat/scripts/four-repo-computer-lifecycle.cjs` demonstration accepts only 25 through 100 mock USDC (inclusive), checked before importing Hardhat or creating a provider/signer. Its five fixed 1000-mock-USDC balances cover both escrow jobs and the configured agent/validator bonds throughout that bounded range. This local fixture range does not restrict the separate unsigned uint128-budget draft API. The four-repository journey selects 25.00; 100.00 is the tested upper boundary. No real funds, public network or operator account are used.
