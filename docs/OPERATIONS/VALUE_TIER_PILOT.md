# From useful job offers to a bounded real-machine pilot

Start with work whose deliverable and independent acceptance test are specific.
A price is a proposed fee, not proof of demand, delivered value or profitability.
Select only jobs within the commissioned apps, account authority and budget.

| Illustrative fee | Useful job | Delivery and independent acceptance |
| --- | --- | --- |
| $100 | Reconcile a small invoice export | Spreadsheet, discrepancy register and source-row references; Node recomputes every total and checks hidden duplicate/missing-row cases |
| $100 | Reproduce and document a website defect | Reproduction steps, environment and bounded patch; Node repeats the failing workflow and regression checks |
| $1,000 | Clean a CRM dataset and prepare an import | Deduplicated file, reversible mapping and conflict queue; Node checks original records, permissions and a test import before separately authorized live changes |
| $1,000 | Build a reporting workflow | Spreadsheet or code, refresh procedure and documentation; Node reruns from original inputs and checks malformed inputs and update behavior |
| $10,000 | Multi-application operations project | Explicit research, implementation, testing and integration stages; independent Nodes evaluate each handoff and the final workflow from original inputs |

These are commissioning designs, not completed customer jobs. Confidential work
uses encrypted inputs and delivery with independent recipient keys. The current
native adapter has whole-account UI authority: put only authorized task accounts
there. It does not implement a credential broker or per-site business-action
enforcement. Use a test workspace until the required authority can be enforced.

## Prepare the pilot

1. Freeze the original inputs, exact source/runtime hashes, acceptance criteria,
   hidden valid and plausible-invalid cases, participant control identities,
   cost ceilings, deadlines and stopping rules. Split calibration and held-out
   groups before any attempt; include job class and price tier in cohort names
   when either changes the economics. Keep sensitive plans private.
2. Run `workforce:plan` with actual reviewer supply and backlog, then
   `workforce:economics` with participant-specific capital, gas, bills and adverse
   outcomes. Three reviewer wallets on one controller do not establish three
   independent reviewers. Correct rejected plans before authorizing a pilot.
3. On the separate Agent and Node Macs, use the companion's native setup and
   commissioning guide. Exercise capture, pointer, keyboard, signed-in test
   sessions, relevant apps, revocation, expiry, cleanup, service restart and
   reboot. Verify that the compute account cannot reach signing secrets. Record
   actual failures as well as successful checks; `doctor` alone is insufficient.
4. Issue only bounded pilot grants. The project coordinator reserves all stages
   and checks remaining work/review time. Keep the same journals and data
   directories across restart. A failed stage requires the documented repair
   work order and fresh authority; it does not create a paid milestone.
5. Have the Node independently reopen or recompute the actual deliverable from
   original inputs. Compare its verdict with an independent outcome oracle.
   Agent screenshots or persuasive explanations do not establish correctness.

## Record the whole cost of useful work

In the private application, `workforce -- human-start` and `human-stop` record
interventions; `workforce -- bill` reconciles actual billed costs, and
`workforce -- operations` exports the durable run records. Use `workforce -- help`
for exact arguments. Include setup, moderation, repair, aborted attempts and
off-system work. Preserve the original records and evidence commitments.

Reconcile payment against finalized receipts and actual beneficiary cash.
Outstanding claims remain outstanding. The native workflow does not automatically
post private jobs or vote on-chain; any authorized settlement uses the reviewed
separate signing workflow. Keep confidential bytes out of public evidence.

Evaluate every predeclared engagement, including abstentions, failed work and
unpaid reviews. Report per-participant and per-cohort net cash, losing-engagement
fractions, useful completion, false approvals on deliberately incorrect work,
human seconds per useful completion and occupied capital. Zero false approvals
from a small sample is not a demonstrated low error rate.

## Decide whether to expand

Stop on an authority violation, missing cost evidence, unreliable recovery or
breached frozen budget/deadline. Use the signed V2 workforce qualification with
the new source and separate cohort loss/supervision limits. Existing production
attestations do not qualify changed source. Retain every failed case in the
denominator and obtain the independent security review required by that gate.

Expand only the scope supported by observed evidence. New models, provider
builds, apps, authority classes or job types need fresh qualification. This
release prepares the pilot; it does not claim actual Mac commissioning, market
demand, live profitability or external assurance.
