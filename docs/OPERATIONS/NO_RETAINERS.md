# No-retainer operations

New work uses calibrated **operator-budget** policies: schema 6 for Agents and Nodes, schema 7 for employers. There is no separate advance review payment. Nodes retain the manager's existing settlement rewards and accept bounded unpaid-review risk. All-engagement costs, independent identities, conservative economic limits and durable reservations remain required.

`checkNewWork` is the operating admission boundary and the default for `npm run economics:admission` and `economics:funding`. It rejects retainer policies. `checkAdmission` remains an offline historical-analysis primitive for previously signed policy formats; it is not the current live intake boundary.

The companion private fleet fixes an operator-budget funding defect: sealing an offer with no review-retainer obligation no longer requires a review-funding policy. New review funding, approval and activation are disabled. Existing escrow credits, refunds, transaction journals, accounting reserves and contract code are preserved for recovery. Migration must not delete the old recovery policy or an existing data directory.

Stop intake, reconcile pending transactions, back up the existing data directories, and enroll newly signed operator-budget policies with new epochs. Signed retainer packets cannot be converted by editing a payment label. Outstanding paid review work must be reconciled under its existing agreement; this release does not erase obligations or automatically reclassify its income. Resume observation before activating new work.

For general computer work, `checkExecutionWindow` requires the complete declared work budget plus a completion reserve (30 seconds by default), counts queued time, and uses the earlier supplied chain or specification deadline. This reduces avoidable late starts; it does not guarantee payment if a buyer settles early or a transaction is delayed. The private Node checks its chain review window before paid inference.

No profitability improvement is claimed from the software tests. Reuse the matched workload and budgets for subsequent economic comparisons, retain failures and unpaid work, and measure provider bills, useful results and human exception time. See [general computer work](GENERAL_COMPUTER_WORK.md).
