## Malformed evidence now fails explicitly

The previous parser used Python's default JSON behavior, which accepts duplicate keys by silently using the last value. An ambiguous report could therefore contain both `"success": false` and `"success": true`, or overwrite a reported error. Although ordinary failed scans already stopped CI, ambiguous evidence should never qualify a release.

The verifier now rejects duplicate keys at any JSON nesting level, nonstandard numeric constants, non-object report roots, malformed results/findings, invalid finding identifiers or metadata, and nontext review rationales. Existing exact source/file-set binding and new/removed/changed finding rejection remain in place. Analyzer findings have not been suppressed or reclassified.

Nine permanent regression tests exercise one valid fixture and **27 rejection scenarios**, including analyzer failures, duplicate success/error keys, missing or malformed findings, unknown/removed/duplicate IDs, severity/confidence drift, source/dependency/configuration changes and nontext review rationale. These checks run in Security Verification CI before the fresh source scan:

```sh
python3 scripts/security/test-slither-review.py
npm run slither:extended
```

The runner still compiles fresh source, preserves both raw JSON reports and verifies them against the source-bound baseline. Updating an analyzer, source file or dependency requires review; no automatic baseline-regeneration path is provided.
