# v0.9.1 UI dependency and build review

This review records the UI dependency choices and remaining installation notices for v0.9.1, reviewed on 2026-09-17. The authoritative versions and package paths are in [`ui/package-lock.json`](../../ui/package-lock.json). A successful build or vulnerability audit does not mean that every installed package is maintained. Final source identity, audit results and CI evidence belong in the release validation record.

## Changes and verification

- Replaced the deprecated `next lint` command with `eslint src --max-warnings 0`. The flat configuration retains Next's `core-web-vitals` rules through `FlatCompat`; the change does not disable warning checks or reduce the source lint target.
- Upgraded the test-only `jsdom` dependency from 25.0.1 to 30.1.0, removing `whatwg-encoding` from the lockfile. Its Node requirement is `^22.22.2 || ^24.15.0 || >=26.0.0`, compatible with the CI target Node 22.23.2.
- Resolved the wallet dependency's missing AsyncStorage module with the official browser implementation described below. No webpack warning filter or empty storage substitute was introduced.

The candidate passed strict lint, TypeScript checking, UI unit tests and a production Next.js build without build warnings. The UI unit suite includes browser-storage behavior, upstream file integrity and exact immutable-terms parity checks. Re-run the commands in [`docs/TESTING.md`](../TESTING.md) against the final release source; this document is not a substitute for that evidence.

All installed dependencies, including development dependencies and wallet packages that are not configured as connectors, remain subject to the full `npm audit --audit-level=low` release gate. No `--omit=dev` exception or audit-severity reduction is used.

## Installed dependencies and configured runtime

[`ui/src/lib/wagmi.ts`](../../ui/src/lib/wagmi.ts) explicitly configures `connectors: [injected()]`. Injected-wallet discovery remains available. The application does not configure the MetaMask SDK, WalletConnect or Safe connectors. RainbowKit is actively used by the providers and connection buttons, so removing it would change the wallet interface.

Wagmi's aggregate connector exports and RainbowKit imports cause webpack to inspect optional SDK modules while building. That dependency traversal does not establish that a connector is enabled at runtime. A supporting scan of the candidate's emitted browser/server JavaScript found no `MetaMaskSDK`, `sdk-communication-layer`, `WalletConnectEthereumProvider`, `relay.walletconnect`, `safe-gateway-typescript-sdk` or `ReactNativeAnonId` markers. Marker absence is not a formal reachability proof, and does not exempt installed packages from audit or maintenance review.

## Official AsyncStorage browser implementation

The MetaMask SDK's optional React Native anonymous-ID storage import previously caused two missing-module build warnings. [`ui/vendor/async-storage-browser`](../../ui/vendor/async-storage-browser/UPSTREAM.md) contains the unmodified official browser implementation from `@react-native-async-storage/async-storage@2.2.0`, its MIT license, the upstream archive integrity and per-file SHA-256 hashes. Local package metadata selects the browser entry and pins `merge-options@3.0.4`; it does not install the native React Native dependency tree.

The webpack alias matches only the exact `@react-native-async-storage/async-storage` request. If invoked in a browser, the implementation performs real asynchronous `localStorage` reads, writes, merges and removals, and propagates actual storage failures. It is not encrypted storage and is not intended for signing keys. Version 2.2.0 provides the legacy default-export API expected by this SDK; replacing it with AsyncStorage 3 requires a caller migration.

[`ui/tests/asyncStorageBrowser.test.ts`](../../ui/tests/asyncStorageBrowser.test.ts) verifies the copied file hashes, anonymous-ID persistence/removal, nested merges, multi-value operations, storage-error propagation and the exact alias. Remove this adapter when the compatible wallet SDK dependency chain no longer imports the legacy package.

## Follow-up criteria

- Upgrade ESLint when the Next/React lint configuration declares support for a maintained ESLint major, preserving the existing lint coverage and strict warning gate.
- Migrate the wallet stack when a compatible RainbowKit/Wagmi combination replaces the legacy SDK chain. Exercise wallet discovery, connection, account/chain changes, transaction review and receipt handling before accepting that migration.
- Re-inventory installation notices after dependency updates and run the full audit gate. A zero-vulnerability audit does not close the unsupported-package follow-up.
