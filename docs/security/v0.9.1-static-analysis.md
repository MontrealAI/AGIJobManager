# v0.9.1 compiler, lint and complete static-analysis review

Reviewed on 2026-09-17 against the source and configuration hashes in the [reviewed baseline](../../scripts/security/slither-reviewed-findings.json). This is internal qualification, not an independent audit. A successful release gate means the exact reviewed evidence matches; it does **not** mean the analyzer returned zero findings.

## Implemented fixes

| Change | Result and verification |
| --- | --- |
| Reject noncanonical ENS address words | Both ENS ownership authorization and optional job-page reads reject a returned word above `uint160.max`, rather than silently truncating its upper bits. Dedicated fuzz and regression cases cover wrapper owners, token approvals, registry resolver pointers, resolver addresses and job-page decoding. Canonical values remain accepted. |
| Validate NameWrapper return values | Both wrapped-name creation and legacy adoption compare the returned node against the independently computed parent/label namehash. A mismatch reverts the whole operation. A regression checks failure followed by a legitimate retry. |
| Complete ERC-165 validation | NFT registration requires canonical `true` for ERC-165 and ERC-721 and canonical `false` for `0xffffffff`. All calls remain gas bounded. Malformed booleans and implementations claiming the invalid interface are rejected. |
| Commit all validator reputation before payments | The reputation pass finishes for every correct validator before the first token transfer. A hostile test token observes both the first and later validator's updated reputation, cannot reenter settlement, and demonstrates complete rollback on a rejected transfer followed by a clean retry. Payment amounts and ordering are unchanged. |
| Use `string.concat` for literal metadata | Five packed-concatenation diagnostics disappear without treating URI/label strings as authentication digests. Existing slash normalization and ENS label validation remain intact. |
| Initialize scalar defaults explicitly | Five uninitialized-local diagnostics disappear. Their previous Solidity defaults were already zero/false; the intended values are now explicit. |
| Emit owner limit-change evidence | `MaxJobPayoutUpdated` and `JobDurationLimitUpdated` expose the previous and new values. A regression verifies emitter and indexed event values. The corresponding two missing-event observations disappear. |
| Clarify byte literals and interface parameters | ENS character checks use direct byte literals; two interface parameter names no longer shadow getter names. No selectors or label rules change. |

The original v0.9.0 mandatory scans contained **50 distinct findings**. Thirteen corresponding findings are removed by the above changes: five packed string concatenations, five scalar defaults, two unchecked wrapper return values and one validator-reputation reentrancy observation. **37 corresponding findings remain explicitly reviewed**. IDs affected by source-line changes have been reviewed against the new descriptions and locations; this is not an assumption that old identifiers certify changed code.

## Compiler and dependency compatibility

The qualified profile uses **Solidity 0.8.37, via IR, optimizer 40 runs, Shanghai EVM, no bytecode metadata hash and stripped revert strings**, with Foundry 1.7.1 and Slither 0.11.6. The [official compiler release](https://github.com/argotorg/solidity/releases/tag/v0.8.37) fixes compiler defects including memory-bytes deletion and mutually recursive stack spilling. The source was recompiled and tested under this profile; older compiler output is not reused.

The native compiler was checked against the [official binary registry](https://binaries.soliditylang.org/linux-amd64/list.json): `0.8.37+commit.f401782d`, SHA-256 `5de843c2c93563cc66425c99a4fb13fdbf32b4c4ae07469480faaf126e14404a`.

OpenZeppelin 4.9.6 retains its pinned upstream package integrity. A narrow, hash-checked installation transformation renames the ECDSA `error` identifiers and converts eight **already declared** memory-safety annotations to current syntax across five compiled files. It does not declare new blocks memory safe or change ECDSA logic. The vendored forge-std interface renames 58 assertion-message parameters. Original/final hashes, upstream provenance, exact scope and removal criteria are in [compiler compatibility](../../scripts/security/COMPILER_COMPATIBILITY.md). Four regression tests prove exact output, idempotence and rejection of unreviewed changes.

The full strict Foundry build completed with `--deny warnings`. The manager's qualified runtime is **24,409 bytes**, leaving **167 bytes** below EIP-170's 24,576-byte limit; creation bytecode is 27,119 bytes before constructor arguments. ENSJobPages runtime is 15,344 bytes. Preserve the complete compiler profile and repeat size and actual deployment checks after any change.

## Forge lint accounting

The v0.9.0 log's 43 diagnostics were individually accounted for. Clearer or checked code removes 22 original occurrences; 21 source-local annotations document intended behavior and bounded conversions. No global lint family is disabled.

- Production annotations cover seven chain-time deadline comparisons, one posting-time percentage cast bounded by its only setter to 1–60, and two address casts immediately preceded by the new `uint160.max` rejection.
- Five test-clock annotations describe deliberate `vm.warp` boundary exercises.
- Six annotations preserve historical `contracts/legacy/AGIJobManagerOriginal.sol` fixture behavior: its deadline comparison and five unchecked transfers. These are **historical fixture exceptions**, not repairs or approval to deploy that contract. Its header explicitly prohibits deployment.

Existing deadline boundary tests, payout/bond fuzzing, malformed-ABI regressions and non-vacuous lifecycle invariants exercise these decisions. Source-local annotations are review evidence, not a statement that timestamps are unmanipulable or legacy transfers are safe.

## All enabled detectors and all severities

Every scan excludes dependencies, test fixtures and the historical legacy contract from **production** findings. No detector category is excluded. The runner explicitly selects Foundry, compiles fresh source, preserves all three raw JSON reports and verifies **each report's complete finding set** against the baseline.

| Report | Enabled detectors | Retained findings |
| --- | ---: | --- |
| All medium/high detectors | 59 | 7 medium; 0 high |
| All reentrancy detectors at every severity | 6 | 30 low; 0 medium/high |
| Complete inventory at every severity | 102 | 7 medium, 36 low, 71 informational, 2 optimization |

There are **116 distinct findings** in the complete inventory and **153 entries across the three overlapping reports**. Every ID has its own location, rationale and evidence reference in the baseline. These counts include accepted observations; they are not unresolved exploits or a zero-findings claim.

| Retained class | Count in complete inventory | Review conclusion |
| --- | ---: | --- |
| Per-validator rounding (`divide-before-multiply`) | 1 medium | Each incorrect validator's slash is floored separately. Multiplying that floor by the incorrect count equals the actual withheld pool; changing the order would change economics and could overallocate. Exact conservation/rounding tests cover it. |
| Mapping-bearing job deletion | 1 medium | Cancellation requires an unassigned job, while voting requires assignment/completion. Its vote mappings are empty; monotonic IDs are never reused. Guarded cancellation and delisting are tested. |
| Selective tuple returns | 5 medium | Optional ENS operations deliberately read only the job fields they need. ABI decoding and call failures remain enforced; unused payout/timer/status fields do not grant authority. Wrapper node return values are now checked separately. |
| Manager interaction observations | 6 low | Money-moving entry points retain `nonReentrant`; incoming balances must change by the exact amount, and terminal state/reserve debits precede outgoing transfers. Later NFT/bond bookkeeping is covered by rollback and callback tests. These assumptions require the configured native USDC. |
| ENS event ordering | 24 low | Owner/manager/self-authorized metadata operations emit outcome events after best-effort external calls. Arbitrary callbacks cannot acquire these roles. Integrations remain owner-selected; consumers must use manager state and transaction/log order for settlement truth. |
| Chain-time comparisons | 6 low | Assignment, challenge and review deadlines intentionally use timestamps, with explicitly tested inclusive/exclusive boundaries. They do not provide randomness or an off-chain timing guarantee. |
| Assembly | 9 informational | Individually reviewed selector encoding, bounded gas/returndata, complete-word decoding, strict booleans/addresses and ABI return construction. Assembly itself is not classified as a defect. |
| Low-level calls | 4 informational | Token return values and balance responses are checked; owner-only ETH rescue and non-USDC generic rescue retain authority/reentrancy guards. |
| Constructor complexity | 1 informational | Independent deployment checks remain explicit; removing them to reduce the branch count would weaken validation. |
| Structural interface inheritance | 1 informational | The optional metadata consumer uses a narrow ABI-compatible view interface; the manager does not need to inherit its consumer's declaration to expose those selectors. |
| Existing underscore naming | 48 informational | Existing ABI input names and self-only hook names are retained for consistency and compatibility. This is a style observation. |
| Long numeric literals | 5 informational | Four are intentionally padded ABI selectors; one is the existing duration default in seconds. Values and bounds remain tested. |
| Existing unindexed address events | 3 informational | Addresses remain correctly encoded in log data. Changing indexing would change the existing event encoding; the tradeoff is filtering efficiency. |
| Array-length caching | 2 optimization | AGI-type loops are capped and NFT queries are static/gas bounded. Caching is a gas micro-optimization, not a demonstrated correctness or liveness repair. |

## Reproduction and evidence gate

After installing the committed root dependencies and compiler/toolchain:

```sh
node --test scripts/security/test-compiler-compatibility.cjs
python3 scripts/security/test-slither-review.py
FOUNDRY_PROFILE=ci forge build --deny warnings
FOUNDRY_PROFILE=ci forge test
npm run slither:extended
```

The old `npm run slither` command is now an alias of the same exact review gate; it no longer produces a misleading clean scan through broad detector exclusions. Raw reports are `build/security/slither-extended.json`, `slither-reentrancy.json` and `slither-all.json` and are retained by CI.

Eleven parser/gate regression tests cover a valid fixture and **33 rejection scenarios**, including complete-inventory drift while the two narrower reports remain unchanged. The verifier binds the production file set, compiler profile, root lockfile, every scan configuration, runner scripts and exact dependency-patch script/manifest. New, removed, duplicated, reclassified or source-changed findings require explicit review. Ambiguous JSON and malformed analyzer results fail closed. There is no automatic baseline-acceptance command.

Local qualification after these source changes completed **36 Foundry tests**, including the nine new security regressions, 256 runs per fuzz test and 64×64 stateful invariant sequences. These results establish the tested scenarios, not universal safety. Final release CI, real-USDC fork/deployment evidence and independent operational review remain separate requirements; see [mainnet readiness](../MAINNET_READINESS.md).
