# Solidity optimizer advisory SOL-2026-7

## Current source correction

The current source retains the released, pinned Solidity **0.8.37** compiler and explicitly excludes its `LoadResolver` (`L`) and `EqualStoreEliminator` (`E`) Yul optimizer passes. These are the two affected passes identified by [Solidity's bug record](https://docs.soliditylang.org/en/latest/bugs.html) and [upstream correction #17116](https://github.com/argotorg/solidity/pull/17116). The remaining sequence and cleanup come from the [0.8.37 default configuration](https://github.com/argotorg/solidity/blob/v0.8.37/libsolidity/interface/OptimiserSettings.h).

This is a source-reviewed interim mitigation, not an upstream-endorsed compiler release or evidence that a deployed contract triggered the bug. On 17 October 2026, the upstream fix was merged but **0.8.38 was still unreleased**; the npm package and official release endpoints did not provide a stable 0.8.38. Do not substitute a nightly build or label 0.8.37 output as 0.8.38. Once a stable fixed compiler is available, upgrading requires a separate exact-source qualification.

Hardhat and Foundry use the same explicit sequence. Optimizer runs remain 40, `viaIR` remains enabled, the target remains Shanghai, metadata bytecode hashes remain disabled and revert strings remain stripped. Deployment preflight rejects the former implicit sequence and altered settings; explorer verification compares the complete saved Standard JSON settings. Compiler warnings and Ethereum size checks remain enabled. No production Solidity source, ABI, storage declaration, eligibility rule or settlement rule is changed.

## Existing deployments and explorer warnings

Etherscan's compiler-version warning can remain visible for 0.8.37, including when the affected passes are excluded. The version-range warning alone does not prove the contract triggers the defect, and this mitigation does not remove that version from the compiler's affected range.

Already deployed runtime bytecode and its original compiler metadata do not change when this source is merged. Preserve each existing deployment's original source, Standard JSON input, constructor arguments, linked-library addresses, receipts and verification records. Do not replace them with a new build. Historical compatibility tests explicitly reconstruct the original optimizer profile and retain the recorded runtime hashes unchanged.

All components of a new deployment must come from the same newly qualified compiler profile, including linked libraries and optional page helpers. Reusing old libraries does not apply this mitigation to those libraries. New bytecode requires new reviewed deployment plans and addresses; reconcile any partially executed plan before preparing another. Deployment, governance handover and activation remain separate operator actions.

## Reproduction and acceptance

```bash
npm ci
npm --prefix hardhat ci
node --test scripts/security/test-yul-stale-bookkeeping.cjs
npm run build
npm run size
npm --prefix hardhat run test:preflight
npm --prefix hardhat run test:deployment
npm --prefix hardhat run test:registry-native
```

The regression checks compiler settings parity and memory/storage behavior using disposable local execution. The full qualification workflows also require contract tests, Foundry fuzz/invariants, retained Slither findings, exact native USDC/ENS fork observations, documentation, UI and release preparation. A compiler profile change invalidates prior build qualification; earlier green runs and historical runtime sizes do not qualify this source.

The pinned Slither 0.11.6 runner orders the unchanged selected detector set by severity and detector name. Its original severity-only ordering could make a shared reentrancy cache omit an already-reviewed finding from the dedicated reentrancy report. The wrapper preserves every selected detector, with no detector exclusions or severity-threshold changes, and the review gate still requires the exact complete findings. Analysis starts with a clean Forge output directory to avoid mixing preliminary lightweight build metadata with the full compiler input/output needed by Slither. Historical scan records remain unchanged.
