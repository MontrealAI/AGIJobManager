# SUCCESSOR Ω threat model

The protected assets are user drafts, retained versions, exact public input/output bytes, operator credentials and signing authority. The Builder handles only public, licensed, nonpersonal content. It does not claim confidential processing or perfect secret detection. Screens, imported JSON, model output and public URLs are untrusted data.

| Threat | Implemented control | Evidence and residual boundary |
| --- | --- | --- |
| XSS or generated-code escape | Text-only UI writes for inputs; escaped reviewed templates; empty iframe sandbox; exact hashed CSP scripts/styles; no network/forms/top navigation | Hostile markup tested in core and real browser. Browser engine correctness remains a dependency. |
| Ambiguous or excessive import | Duplicate-key rejecting parser; exact schemas; prototype-key/Unicode/path/depth/count/size bounds; supported versions only | Malformed JSON, hostile keys, invalid hashes and excessive nesting tests. ZIPs are export-only, so capsule inspection has no decompressor. |
| Forged authority or evidence | Fixed separate evidence/payment/qualification/authority states; checked source/spec/output hashes; artifact reproduction; semantic Chronicle validation; explicit restore | Tampered evidence and broadened flags rejected. Mutable checksums do not establish authorship or independent control. |
| Private-data publication | Public-data consent; recognized secret/email/private-link filters; exact draft preview; no publication API | Known patterns rejected; unknown sensitive data can evade scanning. User must review content and rights. |
| Loopback CSRF, DNS rebinding, replay | Node-only client, literal loopback, exact Host, reject Origin/fetch metadata, secret/HMAC pairing, durable nonces, request sequence, authenticated response | Spoofed host/origin, wrong secret, altered MAC and replay tests. Host OS/operator trust remains necessary. |
| SSRF/redirect bypass | No Builder fetcher; public URL validation; worker accepts no target URL; client literal loopback and redirect error; browser network blocked | Cannot turn a URL into a worker request. Operator public-input retrieval still needs its existing separate controls. |
| Prompt/screen injection | No model interprets instructions in local input; fixed fixture action allowlist outside the driver; no consequential action capability | Arbitrary actions/resources rejected. No live-provider prompt-injection resistance is claimed. |
| Retry amplification or stale state | Before-action durable accounting, expiry, failed-refresh invalidation, timeout revocation, one session/in-flight action, bounded calls/time | Restart/replay/budget/expiry tests and actual stale-observation rejection. Revocation cannot undo completed external effects. |
| Draft loss or cross-origin confusion | Namespaced explicit persistence, export and exact-current-draft replacement consent, explicit console loading, offline handoff blocked | Existing and changed draft preservation and denied-storage browser tests. Other same-origin trusted code remains in the origin trust boundary. |
| Supply-chain substitution | Pinned upstream source hashes/licenses, exact-source build manifest, exported tests, clean rebuild comparison, pinned workflow actions and exact-source qualification | Release assembly attestations bind repository/workflow/source/digest; they do not prove correctness or an independent audit. |
| Financial action or self-admission | No wallet/RPC access, no signer, no grant endpoint, blank spec URI until publication, existing admission/console boundary | Browser wallet/network traps and forged-state tests. Permissionless direct contract calls are outside this Builder's authority. |

No real provider or native desktop credential was used in local qualification. Do not put keys in capsules, local storage, screenshots or workspaces. The fixture's random pairing credentials and private journal are temporary and removed by the rehearsal. Public evidence contains only synthetic fixture content, version/hash observations and results.

Report vulnerabilities through the repository's existing security policy. Preserve failed checks and original evidence; never edit a failed commissioning record into a pass. A future provider adapter must keep signer/compute separation, authenticated scoped/expiring grants, human confirmation for consequential actions, current rights/cost checks, independent reviewer coverage, monitoring and revocation. Until those are actually commissioned, execution remains unavailable.

Guidance reviewed for this implementation: [OpenAI computer use](https://developers.openai.com/api/docs/guides/tools-computer-use), [OpenClaw computer use](https://docs.openclaw.ai/tools/computer-use), [WCAG 2.2](https://www.w3.org/TR/WCAG22/), [GitHub attestations](https://docs.github.com/en/actions/concepts/security/artifact-attestations) and [CLI verification options](https://cli.github.com/manual/gh_attestation_verify). Vendor documentation describes vendor capabilities, not measured capability of this Builder.
