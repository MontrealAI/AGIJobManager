# v1.0.4 publisher/operator notice review

This is an internal software and documentation review, not a legal opinion, external audit or certification of a live service.

## Scope

- Replace overstated source-comment claims about automatic acceptance, jurisdiction, intermediary status, exclusive user duties and absence of refunds with fact-based role disclosure, prospective terms and mandatory-law exceptions.
- Preserve MIT permissions and disclaimers. Provide an independent operator template without imposing new software-use conditions or importing the GoalOS publication's restricted license.
- Disclose actual owner/moderator powers, successful-job fees, ENS/host roles, public-data exposure and limits of support. No publisher/operator role or fee beneficiary is invented for an unconfigured deployment.
- Synchronize the console's full notice with the source through `docs:terms`, with an exact-text check in documentation CI. Link the legal center from current interfaces and deployment guides.
- Remove persisted acknowledgement from browser sessions. Reopening/restoring a page and withdrawing acknowledgement cancel a pending transaction review. Existing account/network/manager invalidation remains in force.
- Make deployment/readiness output explicit that technical checks do not assess legal status. No identity-document collection, new analytics, legal approval flag or public-chain operation is added.

## Contract compatibility

Only the manager's opening source comment changes. Everything following that comment is byte-for-byte identical to v1.0.3. All other Solidity files are unchanged. The qualified compiler produces the same ABI, creation bytecode and deployed runtime. Storage, links, powers, pauses, payouts, reserves and disabled NFT default remain unchanged. Original deployment source and agreements are not rewritten.

The static-analysis review updates only the manager comment fingerprint and root package-lock version fingerprint. Finding identities, dispositions, detector settings and compiler/dependency patches remain preserved; exact-source CI must reproduce the reviewed finding set.

## Verification scope

The release must pass documentation consistency, real-browser stale-acknowledgement/review-cancellation regressions and the existing five exact-source workflows. These cover contract shards, deployments, browser/UI behavior, security/fuzz/invariants/static analysis, pinned mainnet forks and documentation. Source-bound cutover evidence is regenerated for this release. Final executed results and run identifiers are recorded in the v1.0.4 release's validation record; a planned check is not a result.

Independent security review, local legal advice, valid operator adoption/acceptance, translations where required, actual signer control and live-instance commissioning remain separate. No claim of full immunity or worldwide compliance is made.
