# Recovery and rollback

Keep the prior HTML and capsule before selecting an improvement. Local rollback restores a previously chosen candidate; it does not reverse public data, contract payments or completed external actions. Restore validates, previews and requires explicit confirmation; historical authority cannot reactivate.

If the browser loses storage, open a downloaded HTML or import a capsule. If the engine is edited, retain the original reader and source manifest, run the exported tests, rebuild into a new directory and inspect the restored artifacts. Unknown schema versions are rejected rather than silently migrated. Never paste secrets into diagnostic output.

If a worker call times out, the fixture session is revoked. Do not reset its journal to evade call/time limits. Inspect the durable attempt history and reconcile any effect before a separately authorized new session. No live-provider recovery is implied by the fixture.

For contract pause, disputes, rejected transfers, pending claims, replaced/uncertain transactions and existing review credits, follow the unchanged operator/recovery guides in `source/docs/OPERATIONS/`. Original liabilities remain with their original contracts and controllers.

For a software/website regression, revert through a reviewed PR, rerun applicable checks, and explicitly redeploy the reviewed Pages SHA. Never move published tags or overwrite an existing release asset. A later release needs its own source and qualification.
