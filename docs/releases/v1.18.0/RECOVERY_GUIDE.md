# Recovery and rollback

Never overwrite the only copy of the first deployment's source, artifacts, compiler input or journal. Keep existing jobs, review credits, bonds and deferred claims on their original manager. A new deployment does not migrate them.

A failed deployment command may already have broadcast. Reconcile its unique journal and canonical receipts before any retry; rerunning deployment does not resume the old attempt. Follow the Hardhat guide's keyless verification recovery and the operator incident-response guide. Do not edit receipt success fields or bypass readiness failures.

Fresh deployment starts paused. Preserve ownership acceptance and readiness evidence separately. Pausing intake does not pause ordinary settlement; settlement pause delays exits and lifecycle clocks. Use the intended owner's incident policy and reconcile reserved liabilities before any separately authorized action.

For local Builder work, retain downloaded HTML, the original Alpha dossier and complete-history capsules before changes. Requesting a download does not confirm that it was saved. Use explicit browser save when available, keep a verified exported copy, and confirm the mapping again after loading a saved transfer. Clearing a saved browser copy marks retained open history as unsaved; an empty workspace stays clean. Clearing browser storage is not a backup; quota or unavailable storage must not be treated as a successful save. Rollback restores a chosen local version; it cannot reverse payments or completed external effects. Keep durable worker history and reconcile uncertain outcomes before another authorized attempt.

For a software regression, use a reviewed correction, repeat qualification and publish a new version. Never move a published tag or replace release assets. Website publication, deployed-contract changes and intake activation each require their own authorization.

For the optional metadata router, preserve its original non-overwriting journal. Use only the guide's existing-address recovery path after reconciling canonical creation/runtime evidence. A `verified_unconfigured` result does not authorize attaching it to a manager or changing metadata settings. Never treat a failed explorer request as permission to deploy a replacement.

Recover Builder sources using the complete exported inventory and its strict v2 `SOURCE.json`, including selected commit/tree, package checksum and full source manifest. Do not replace its selected commit with a later website/release wrapper SHA. The release manifest records both identities; the archived selector and all source bytes must agree before an offline rebuild. A source edit requires a newly reviewed real code commit and subsequent selector update.
