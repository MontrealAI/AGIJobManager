# AGIJobManager v1.19.5 release notes

v1.19.5 adds a bounded developer adapter for complete Alpha transformation campaigns and a separate finite source/qualification policy. Start with the [entry guide](START_HERE.md) and [adapter contract](../../successor/TRANSFORMATIONAL_WORK.md).

| Capability | Supported behavior | Limit |
| --- | --- | --- |
| Native campaign inspection | Installed compatible Alpha inspector validates the full retained campaign; expected runtime bindings are supplied independently | Imported files select no code and grant no authority |
| Recovery | Original UTF-8 campaign bytes, charter, evaluation instrument, epoch and runtime binding remain available for deterministic reinspection | Hashes bind bytes; they do not prove semantic truth, independent review or trustworthy freeze timing |
| USDC boundary | Explicit six-decimal charter cap and USDC route checked separately from other currencies | Current native zero-currency pilot supports free inspection only; positive paid proposals are unsupported |
| Packaging | Explicit finite source inventory and source-specific qualification/publication requirements | A source inventory or local test pass is not completed exact-final-source qualification |

The adapter leaves deployment, specification URI, job duration, details and transaction unset. It performs no networking, persistence, worker execution, job posting, token approval, signing, vote or settlement. Alpha owns campaign discovery, purpose, formulation, evaluation and witnesses; Fleet owns isolated execution/review; Manager and Jobs retain separate USDC and AGIALPHA lifecycles. No exchange between those currencies is introduced.

Credential-shaped input and bounded URL checks are rejection rules, not a complete privacy classification or rights clearance. Use public, non-personal content only. The paper’s broad research claims, real-machine performance, sustained economic benefit and organizational independence are not established by this adapter.

The inherited Builder remains at its immutable v1.19.4 code pin. Historical v1.19.4 release records, deployed contracts, compiler profile, dependency resolutions, addresses and recovery obligations retain their original identities. Private Fleet/Agent/Node versions remain separate. This wrapper changes software labels, not deployed bytecode or paused-intake status.

Read the [validation boundary](VALIDATION.md) before treating a download as qualified, and [recovery instructions](RECOVERY_GUIDE.md) before changing an existing installation. No new deployment, mainnet/ENS operation, production activation or independent audit is claimed.

The [retained 19 October ENS configuration evidence](../../deployments/ENS_CONFIGURATION_RETAINED_2026-10-19.md) adds a later historical helper snapshot without changing the original deployment record or transaction defaults. Its actual fee exceeded the original ceiling, and the separate explorer exact-source-input match remains unresolved; publication does not convert either into a pass.
