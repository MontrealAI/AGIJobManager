ENGLISH — SOURCE PREVIEW 0.1.0-source-preview.2, NOT QUALIFIED FOR MAINNET USE

This package signs an exact reviewed Ethereum Mainnet type-2 envelope through USB Ledger and lets you download the private signed file. It never submits a transaction.

1. The deployment coordinator must first preserve the exact intent durably and acquire the required wallet locks. Obtain the independent unsigned transaction hash and policy digest from the reviewed decision pack. This package does not prove repository provenance or campaign history.
2. Run npm ci --ignore-scripts --no-audit --no-fund, npm test, npm run build, then npm start. Open http://127.0.0.1:4173/ in a WebHID-capable desktop browser. Browser and physical-device acceptance are still pending.
3. Enter the exact unsigned bytes, independent unsigned hash, reviewed policy JSON, independent policy digest and actual derivation path. Review all outputs. Authorize only this local signing attempt.
4. During an explicitly owner-operated rehearsal, click Connect USB, verify address and sign. Confirm the account on the Ledger itself. The browser blocks online Ledger context/reporting; signing may fail or require blind signing. Do not weaken the policy to force success.
5. First download the full private recovery file. The separate private coordinator-import download produces only {"raw":"<canonical signed transaction>"}, matching the supplied Manager R2 and Alpha R4 coordinator source format. It rechecks the independent review pins, exact capability/envelope, recovered sender, signed hash and current expiry. This is a source-only format bridge, not qualified coordinator integration. Keep both files local and private. No broadcast happened. Original source/build, campaign, durable intent, nonce, expiry, chain-state and wallet/campaign-lock gates remain required in the separately reviewed coordinator before durable signed-hash recording and separately authorized relay.

STOP / RECOVERY: On expiry, mismatch, rejection, lost response or disconnect, do not automatically retry. Return to coordinator recovery. At expiry the import export refuses COORDINATOR_IMPORT_EXPIRED_DO_NOT_RELAY; the full private recovery file remains downloadable and is marked EXPIRED_SIGNED_CAPABILITY_DO_NOT_RELAY. Preserve it, including when a valid signature returns late. Local expiry does not cancel an Ethereum signature, and {raw} JSON has no enforceable expiry. Never post signed files or APDU logs publicly. No seed, PIN, private key or account credential is requested. Browser smoke remains BLOCKED; physical device and actual coordinator integration remain unqualified.

FRANÇAIS — APERÇU SOURCE 0.1.0-source-preview.2, UTILISATION MAINNET NON QUALIFIÉE

Cet outil signe une enveloppe Ethereum Mainnet de type 2, précisément révisée, avec un Ledger USB et permet le téléchargement privé du fichier signé. Il n'envoie aucune transaction.

1. Le coordinateur de déploiement doit d'abord conserver durablement l'intention exacte et acquérir les verrous des portefeuilles. Obtenez le hachage indépendant de la transaction non signée et l'empreinte indépendante de la politique dans le dossier de décision révisé. Cet outil ne prouve ni la provenance du dépôt ni l'historique de la campagne.
2. Exécutez npm ci --ignore-scripts --no-audit --no-fund, npm test, npm run build, puis npm start. Ouvrez http://127.0.0.1:4173/ dans un navigateur de bureau compatible WebHID. Les essais du navigateur et du Ledger physique restent à effectuer.
3. Saisissez les octets exacts, le hachage indépendant, la politique JSON révisée, son empreinte indépendante et le véritable chemin de dérivation. Vérifiez le résumé. Autorisez uniquement cette tentative locale de signature.
4. Lors d'un essai explicitement réalisé par le propriétaire, sélectionnez Connect USB, verify address and sign. Confirmez l'adresse sur le Ledger. Le navigateur bloque les services Ledger en ligne : la signature peut échouer ou exiger une signature à l'aveugle. N'affaiblissez pas les contrôles pour forcer la réussite.
5. Téléchargez d'abord le fichier privé complet de reprise. Le téléchargement privé distinct pour le coordinateur contient uniquement {"raw":"<transaction signée canonique>"}, conformément au format des sources Manager R2 et Alpha R4 fournies. Il revérifie les empreintes indépendantes, la capacité complète, l'enveloppe exacte, le signataire, le hachage signé et l'expiration courante. Il s'agit uniquement d'une passerelle de format source; l'intégration réelle reste non qualifiée. Conservez les deux fichiers en privé, localement. Aucun envoi n'a eu lieu. Les contrôles de la source originale, de la compilation, de la campagne, de l'intention durable, du nonce, de l'expiration, de la chaîne et des verrous du portefeuille et de la campagne restent obligatoires dans le coordinateur révisé avant l'enregistrement durable du hachage et toute transmission autorisée séparément.

ARRÊT / REPRISE : En cas d'expiration, de divergence, de refus, de réponse perdue ou de déconnexion, ne relancez pas automatiquement. Revenez à la procédure de reprise du coordinateur. À l'expiration, l'exportation d'importation refuse COORDINATOR_IMPORT_EXPIRED_DO_NOT_RELAY; le fichier privé complet reste téléchargeable avec EXPIRED_SIGNED_CAPABILITY_DO_NOT_RELAY. Conservez-le, y compris si la signature revient tard. Cette expiration n'annule pas une signature Ethereum et le JSON {raw} n'impose aucune expiration. Ne publiez jamais les fichiers signés ni les journaux APDU. Aucun secret de récupération, NIP, clé privée ou identifiant de compte n'est demandé. L'essai navigateur reste BLOQUÉ; les essais du Ledger physique et de l'intégration réelle restent non qualifiés.
