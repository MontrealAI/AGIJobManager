This extends the retained source-preview.2 signer. Use the campaign dashboard for checked native-coordinator handoff, private recovery and exact one-shot relay controls. Before launch, the integration owner must provide one independently reviewed immutable campaign, its canonical SHA-256 digest, the exact supported clean coordinator checkout/build/plan, and private session/state/actor-lock directories outside all source checkouts. The campaign must bind the actual route/token/decimals, new graph, governor/creator/fee/treasury roles, numeric policy, every exact envelope and expiry. Current supported scopes are nine Manager core creations, or five Alpha creations plus two separately governed bindings. Jobs hardware/external-signature support is reported separately; do not substitute an old {raw} export or another schema. An absent compatibility entry is a blocker.

Build and verify the package, without using a wallet:
  npm ci --ignore-scripts --no-audit --no-fund
  npm test
  npm run build

Launch only a reviewed campaign (replace the three placeholders with the owner's exact reviewed local values; do not create an unreviewed campaign merely to start the app):
  node bridge/start.mjs --campaign /absolute/private/reviewed-campaign.json --reviewed-campaign-sha256 EXACT_REVIEWED_CANONICAL_SHA256 --actor-lock-directory /absolute/private/shared-actor-locks --state /absolute/private/campaign-state

The campaign JSON must be an owner-only ordinary file (0600), with no symlink aliases. The digest is the canonical campaign digest independently approved for that exact content, not an automatically trusted hash of a newly edited file. The required --actor-lock-directory must exactly match campaign.coordinator.lockDirectory and the approved common directory for campaigns sharing these accounts. Launch registers this canonical directory in an owner-only per-OS-account actor-lock policy (on macOS: ~/Library/Application Support/ManualLedgerCampaignCompanion/actor-lock-policy.json); another directory is refused. This does not remove native coordinator locks. Read the compatibility matrix and README for exact required paths and build qualification; the package does not invent them.

Open the numeric 127.0.0.1 dashboard address printed by the bridge, using the supported desktop browser. A separate numeric loopback origin isolates the signer. No token or signed bytes appear in either URL. The browser session token stays in memory.

3. Enter your actual derivation path; no default is selected. At first connection or actor/path change, confirm the full address on the physical Ledger. Same-account USB reuse rechecks the account before later operations. Each transaction still needs your manual Ledger approval. The browser summary is not the device display; arbitrary initcode is not promised clear signed. Remote Ledger context/telemetry are blocked; the device may require blind signing or refuse.
4. The checked signature is automatically carried to the coordinator and privately preserved. The child retains full private recovery until the exact durable acknowledgement returns. Save the full recovery file if handoff/downloads fail; keep the signer frame open until recovery is confirmed. An expired signature remains executable on Ethereum: preserve DO_NOT_RELAY, and never infer that time cancelled it.
5. Relay is disabled by default. A separate reviewed immutable relay policy plus explicit runtime --relay enables the exact native per-step acknowledgement button. This first version requires that additional click after each manual signature; no command copying or acknowledgement typing is needed. It requests the coordinator's one-shot relay only. Unknown results stop for read-only recovery, with no automatic resend, fee bump or replacement.
6. After submission, the dashboard observes the exact known hash every five seconds, up to 360 observation cycles or 30 minutes per operation. A cycle may perform multiple read-only RPC checks. At the bound it stops for read-only recovery without resending. Exact canonical verification can prepare the next already-reviewed operation. Explorer/configuration status remains separate; comprehensive authority and activation stay false until their actual evidence exists.

If source/account/chain/fees/policy change, a receipt changes, a foreign lock appears, the device rejects/disconnects, or output is lost: STOP. Use Observe & recover. Preserve the private state and any signed capability. Never delete actor locks by age, rebuild a lost intent, repeat a signature or infer relay permission from a missing receipt. The narrowly scoped --recover-dead-bridge-owner option is only for a proven dead bridge process; it preserves signing markers and requires successful read-only classification before progression.
